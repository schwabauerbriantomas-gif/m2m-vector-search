Beyond ANN

What Makes M2M Different

M2M doesn't compete with FAISS on raw speed. It competes on capabilities FAISS cannot offer.

🧠

Adaptive Gaussian Splats

Each vector carries learnable κ (concentration) and α (importance) that evolve with query feedback — no reindexing needed.

⚡

Energy-Based Uncertainty

Every result carries a confidence score derived from the local energy landscape topology. Know when to trust a result.

🔄

Online Hebbian Learning

Splat parameters adapt in real-time from user feedback. α += lr·α on relevant, decay on irrelevant. Zero retraining.

🧩

SOC Consolidation

Self-Organized Criticality automatically prunes low-contribution splats. The system reaches avalanches and relaxes — like neuronal memory.

🔍

Hybrid Semantic Search

BM25 + vector with Reciprocal Rank Fusion, temporal decay, and auto-categorization. The best of keyword and semantic in one query.

🚀

Multi-Backend GPU

CPU, NVIDIA CUDA, and AMD Vulkan through a single API. Transparent backend selection. RTX 3090 hits 1,338 QPS brute-force.

Honest Assessment

M2M vs The World

🟢 Use M2M when...

  • ✓ Building AI agents with persistent, adaptive memory
  • ✓ Need confidence/uncertainty scores on search results
  • ✓ Want online learning without reindexing
  • ✓ Have a GPU and <10M vectors (CUDA brute-force)
  • ✓ Need hybrid BM25 + vector fusion in one engine
  • ✓ Want automatic memory consolidation (SOC pruning)

🔴 Use FAISS / HNSW when...

  • ✗ Need billion-scale ANN with maximum QPS
  • ✗ Pure vector search, no adaptive learning needed
  • ✗ Production systems with SIMD-optimized C++ backends
  • ✗ Need HNSW graph-based approximate search
  • ✗ Want Milvus/Qdrant managed vector database features
